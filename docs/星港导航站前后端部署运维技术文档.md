## 一、方案概述

### 1.1 升级背景

「星港导航」此前为纯静态单文件页面，存在两个限制：① 修改数据仅存于操作者浏览器的 localStorage，其他访客看不到；② 无法实现真正的登录鉴权（静态页面无法安全保存凭据）。本次升级目标：**改造为「前端静态页 + PHP API + MariaDB」前后端架构**，实现预置账号登录后才能修改页面内容，且数据全体访客共享。

### 1.2 架构原理

```
访客浏览器（index.html，纯静态前端，零依赖）
      │  fetch JSON（HTTPS）
      ▼
PHP API 层（api/：auth.php / links.php / note.php）
      │  PDO（仅服务器内部可达 127.0.0.1:3306）
      ▼
MariaDB（三张表：nav_links / nav_note / nav_admin）
```

**权限模型**：

| 角色 | 可见/可操作 |
|------|-----------|
| 未登录访客 | 浏览全部站点卡片、搜索、时钟；所有写接口返回 401 |
| 管理员（登录后） | 编辑模式（增删改链接）、便签读写、退出登录 |

### 1.3 主机环境（本次实测）

| 站点域名 | https://techprobe.lxi.be/（HTTPS 由主机商配置） |

## 二、环境要求与预检

| 项目 | 要求 | 本次实测 |
|------|------|---------|
| 操作端 | Windows + Python 3.6+（paramiko） | Python 3.12.13 |
| 主机端 | PHP 8.x（需 pdo_mysql/session）、MariaDB/MySQL | PHP 8.3.36 / MariaDB 10.11.14 |
| 网络 | 出站可达 panel.lxi.be:2222 与站点 443 | 已验证 |

**SSH 环境探查脚本**（确认 PHP 版本、扩展、目录结构）：

```python
import os, paramiko
c = paramiko.SSHClient()
c.set_missing_host_key_policy(paramiko.AutoAddPolicy())
c.connect('panel.lxi.be', port=2222, username='<SSH用户>',
          password='<面板密码>', look_for_keys=False, allow_agent=False)
for cmd in ['php -v | head -1',
            'php -m | grep -iE "mysqli|pdo_mysql|session"',
            'ls -la ~/public_html']:
    _, o, _ = c.exec_command(cmd, timeout=30)
    print('$ ' + cmd); print(o.read().decode('utf-8', 'replace'))
c.close()
```

判读要点：PHP 扩展四项齐备即可部署；`public_html` 为网站根目录（Virtualmin 布局）。

**两个实测发现（重要）**：
1. SSH 会话内无法直连数据库（`mysql` 客户端报 socket/连接错误）——共享托管只允许 Web 进程（PHP）访问数据库。因此**建表、改密等数据库操作都要通过上传一次性 PHP 脚本经 HTTP 触发执行，用完立即删除**。
2. 数据库密码与面板/SSH 密码**不相同**，需在控制面板 Databases 页查看，或用面板提供的连接串。

## 三、数据库设计与初始化

### 3.1 表结构（建表 SQL）

```sql
CREATE TABLE IF NOT EXISTS nav_links (
  id VARCHAR(20) PRIMARY KEY,          -- 链接唯一标识
  name VARCHAR(100) NOT NULL,           -- 显示名
  url VARCHAR(500) NOT NULL,            -- 完整网址
  domain VARCHAR(200) NOT NULL,          -- 显示用域名
  grp VARCHAR(20) NOT NULL DEFAULT 'office',  -- 分组：office/life
  c1 VARCHAR(20) DEFAULT '#3B82F6',     -- 渐变起始色
  c2 VARCHAR(20) DEFAULT '#818CF8',     -- 渐变结束色
  pos INT NOT NULL DEFAULT 0           -- 排序
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

CREATE TABLE IF NOT EXISTS nav_note (
  id INT PRIMARY KEY,                   -- 固定为 1（单条便签）
  content TEXT,                         -- 便签内容
  updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

CREATE TABLE IF NOT EXISTS nav_admin (
  id INT PRIMARY KEY,                   -- 固定为 1（单管理员）
  username VARCHAR(50) NOT NULL,
  pass_hash VARCHAR(100) NOT NULL       -- bcrypt 哈希
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

### 3.2 初始化方式（一次性 PHP 脚本）

因 SSH 无法直连数据库，初始化流程为「上传脚本 → HTTP 触发 → 删除脚本」：

**init 脚本**（建表 + 写入管理员 + 便签占位）：

```php
<?php
// 一次性初始化脚本：上传为随机文件名（如 lx-init-x7k9.php），执行后立即删除
header('Content-Type: text/plain; charset=utf-8');
$pdo = new PDO('mysql:host=127.0.0.1;port=3306;dbname=<数据库名>;charset=utf8mb4',
  '<数据库用户>', '<数据库密码>', [PDO::ATTR_ERRMODE => PDO::ERRMODE_EXCEPTION]);

// 建表（同 3.1 SQL，此处略）
// 管理员：用 bcrypt 生成哈希后写入
$hash = password_hash('<管理员密码>', PASSWORD_BCRYPT);
$pdo->prepare("INSERT IGNORE INTO nav_admin (id, username, pass_hash) VALUES (1, 'admin', ?)")
    ->execute([$hash]);
$pdo->exec("INSERT IGNORE INTO nav_note (id, content) VALUES (1, '')");
echo "INIT-DONE\n";
```

**seed 脚本**（写入 22 条默认链接，结构与 init 相同，核心逻辑）：

```php
$links = [
 ['d1','网易邮箱','https://mail.163.com','mail.163.com','office','#60A5FA','#2563EB'],
 // ... 共 22 条，格式：[id, 名称, 网址, 域名, 分组, 渐变色1, 渐变色2]
];
$pdo->exec('DELETE FROM nav_links');
$st = $pdo->prepare('INSERT INTO nav_links (id,name,url,domain,grp,c1,c2,pos) VALUES (?,?,?,?,?,?,?,?)');
$pos = 0;
foreach ($links as $l) { $st->execute([$l[0],$l[1],$l[2],$l[3],$l[4],$l[5],$l[6],$pos++]); }
```

**安全要求**：
1. 一次性脚本文件名带随机串（不可猜测），**执行完立即通过 SFTP 删除**，并 HTTP 访问验证返回 404
2. 脚本内凭据执行后即随文件销毁，不残留

## 四、后端 API 实现

### 4.1 接口清单

| 接口 | 方法 | 鉴权 | 功能 |
|------|------|------|------|
| `api/auth.php` | `POST {action:"login"}` | 无 | 登录（校验 bcrypt，建会话） |
| `api/auth.php` | `POST {action:"logout"}` | 无 | 登出（销毁会话） |
| `api/auth.php` | `GET ?action=status` | 无 | 查询会话状态 |
| `api/links.php` | `GET` | 无 | 返回全部链接（数组） |
| `api/links.php` | `POST {links:[...]}` | 需登录 | 整份替换保存链接 |
| `api/note.php` | `GET` | 需登录 | 读取便签 |
| `api/note.php` | `POST {note:"..."}` | 需登录 | 保存便签 |

### 4.2 config.php（公共配置，完整源码·脱敏）

```php
<?php
declare(strict_types=1);

const DB_HOST = '127.0.0.1';
const DB_PORT = 3306;
const DB_NAME = '<数据库名>';
const DB_USER = '<数据库用户>';
const DB_PASS = '<数据库密码>';

function db(): PDO {
    static $pdo = null;
    if ($pdo === null) {
        $pdo = new PDO(
            'mysql:host=' . DB_HOST . ';port=' . DB_PORT . ';dbname=' . DB_NAME . ';charset=utf8mb4',
            DB_USER, DB_PASS, [PDO::ATTR_ERRMODE => PDO::ERRMODE_EXCEPTION]);
    }
    return $pdo;
}

function start_session(): void {
    if (session_status() === PHP_SESSION_ACTIVE) return;
    $secure = !empty($_SERVER['HTTPS']) && $_SERVER['HTTPS'] !== 'off';
    session_set_cookie_params([
        'lifetime' => 0, 'path' => '/',
        'httponly' => true,            // JS 不可读取会话 Cookie
        'samesite' => 'Lax',           // 基础 CSRF 防护
        'secure'   => $secure,         // HTTPS 下仅加密传输
    ]);
    session_start();
}

function json_out($data, int $code = 200): void {
    http_response_code($code);
    header('Content-Type: application/json; charset=utf-8');
    header('Cache-Control: no-store');
    echo json_encode($data, JSON_UNESCAPED_UNICODE);
    exit;
}

function require_auth(): void {          // 写接口鉴权
    start_session();
    if (empty($_SESSION['admin'])) {
        json_out(['ok' => false, 'error' => 'unauthorized'], 401);
    }
}

function check_csrf(): void {             // 写操作须带自定义请求头
    $h = strtolower($_SERVER['HTTP_X_REQUESTED_WITH'] ?? '');
    if ($h !== 'xmlhttprequest') {
        json_out(['ok' => false, 'error' => 'bad-request'], 400);
    }
}

function read_json_body(): array {
    $raw = file_get_contents('php://input');
    $data = json_decode((string)$raw, true);
    return is_array($data) ? $data : [];
}
```

### 4.3 auth.php（登录核心逻辑）

```php
<?php
require __DIR__ . '/config.php';

// GET ?action=status —— 会话状态
if ($_SERVER['REQUEST_METHOD'] === 'GET' && ($_GET['action'] ?? '') === 'status') {
    start_session();
    json_out(['ok' => true, 'logged' => !empty($_SESSION['admin']),
              'user' => $_SESSION['admin'] ?? null]);
}

if ($_SERVER['REQUEST_METHOD'] === 'POST') {
    $body   = read_json_body();
    $action = (string)($body['action'] ?? '');

    if ($action === 'logout') {
        start_session();
        $_SESSION = [];
        session_destroy();
        json_out(['ok' => true]);
    }

    if ($action === 'login') {
        $u = trim((string)($body['user'] ?? ''));
        $p = (string)($body['pass'] ?? '');
        start_session();
        // 服务端限速：同一会话 60 秒内失败 5 次即锁定
        if (($_SESSION['lock'] ?? 0) > time()) {
            json_out(['ok' => false, 'error' => 'locked'], 429);
        }
        if ($u !== '' && $p !== '') {
            $row = db()->query('SELECT username, pass_hash FROM nav_admin WHERE id = 1')
                       ->fetch(PDO::FETCH_ASSOC);
            if ($row && hash_equals($row['username'], $u)
                    && password_verify($p, $row['pass_hash'])) {
                $_SESSION['fails'] = 0;
                session_regenerate_id(true);   // 防会话固定攻击
                $_SESSION['admin'] = $row['username'];
                json_out(['ok' => true, 'user' => $row['username']]);
            }
        }
        $_SESSION['fails'] = (int)($_SESSION['fails'] ?? 0) + 1;
        usleep(300000);                        // 失败固定 300ms 延迟
        if ($_SESSION['fails'] >= 5) {
            $_SESSION['lock'] = time() + 60;
            $_SESSION['fails'] = 0;
        }
        json_out(['ok' => false, 'error' => 'bad-credentials'], 401);
    }
}
json_out(['ok' => false, 'error' => 'bad-request'], 400);
```

### 4.4 links.php / note.php（数据接口要点）

- **links.php GET**：`SELECT ... ORDER BY pos` → JSON 数组（公开）
- **links.php POST**：鉴权 + CSRF 头校验 → 事务内 `DELETE` 全表 + 批量 `INSERT`（整份替换，避免逐条同步的中间态）；每条做长度/格式校验（名称≤50字、URL 必须 `https?://` 前缀并补全、分组白名单 office/life、色值 `#[0-9A-Fa-f]{6}` 校验）
- **note.php**：鉴权后读写 `nav_note` 表单条记录；内容截断 20000 字
- 写失败返回 401（未登录）/ 400（校验不过）/ 500（数据库错误）

### 4.5 前端改造要点

| 改造点 | 说明 |
|--------|------|
| 数据加载 | 启动时 `GET api/links.php` 覆盖默认数据；失败则显示内置默认 22 条（离线兜底） |
| 会话恢复 | 启动时 `GET api/auth.php?action=status`，已登录则直接解锁编辑/便签并拉取便签 |
| 登录流程 | 表单 → `POST auth.php` → 成功后切换 `body.logged` 状态类，显示编辑/便签/退出按钮 |
| 保存 | 增删改后调用 `POST links.php`（带 `X-Requested-With` 头），失败弹 toast 提示 |
| 便签 | 打开时拉取、输入停止 800ms 后自动保存到服务端 |
| 退出 | 调用 `POST auth.php {action:"logout"}` 销毁会话，前端收回编辑权限 |
| 搜索 | 搜索/网址直达改用 `window.open(…,'_blank','noopener')` 在新标签页打开 |

### 5.1 文件清单与上传

上传 5 个文件：`index.html`、`api/config.php`、`api/auth.php`、`api/links.php`、`api/note.php`。

**自动化上传脚本**（备份 → 上传 → SHA-256 校验一体）：

```python
import os, paramiko, time, hashlib
c = paramiko.SSHClient()
c.set_missing_host_key_policy(paramiko.AutoAddPolicy())
c.connect('panel.lxi.be', port=2222, username='<SSH用户>', password='<面板密码>',
          look_for_keys=False, allow_agent=False)
sftp = c.open_sftp()

# 1) 备份现网 index.html（带时间戳，多版本留档）
ts = time.strftime('%Y%m%d-%H%M%S')
sftp.rename('/workspace/public_html/index.html',
            '/workspace/public_html/index.html.bak-' + ts)

# 2) 确保 api 目录存在
try: sftp.stat('/workspace/public_html/api')
except IOError: sftp.mkdir('/workspace/public_html/api')

# 3) 上传并设权限
files = {
  '<本地>/index.html':      '/workspace/public_html/index.html',
  '<本地>/config.php':      '/workspace/public_html/api/config.php',
  '<本地>/auth.php':        '/workspace/public_html/api/auth.php',
  '<本地>/links.php':       '/workspace/public_html/api/links.php',
  '<本地>/note.php':        '/workspace/public_html/api/note.php',
}
for lp, rp in files.items():
    data = open(lp, 'rb').read()
    with sftp.open(rp, 'wb') as f: f.write(data)
    sftp.chmod(rp, 0o644)

# 4) 服务器端 SHA-256 与本地比对（防传输损坏）
_, o, _ = c.exec_command('sha256sum /workspace/public_html/index.html')
print(o.read().decode())
sftp.close(); c.close()
```

## 六、安全设计说明

1. **凭据管理**：数据库密码仅存在于服务器端 `api/config.php`（已列入 `.gitignore`，不进仓库）；公开仓库提供 `config.sample.php` 模板。操作文档中的凭据一律占位符。面板密码曾以对话流转，建议部署后在面板修改并启用 2FA（本主机默认已启用）。
2. **密码存储**：管理员密码仅存 bcrypt 哈希（`password_hash`/`password_verify`），源码与数据库中均无明文；登录比较用 `hash_equals` 防时序攻击。
3. **会话安全**：Session Cookie `HttpOnly + SameSite=Lax`（HTTPS 下加 `Secure`）；登录成功 `session_regenerate_id` 防会话固定；退出销毁会话。
4. **暴力破解防护**：同一会话 60 秒内连续失败 5 次锁定 60 秒；每次失败固定 300ms 延迟。
5. **CSRF 防护**：写操作要求 `X-Requested-With: XMLHttpRequest` 自定义头（跨站表单无法携带）+ SameSite Cookie 双重防护。
6. **输入校验**：链接数量上限 200、名称 50 字、URL 强制 https 前缀并校验、分组白名单、色值正则校验；便签 2 万字截断。
7. **最小暴露面**：数据库仅服务器内部可达；SSH/SFTP 仅操作者使用；一次性脚本即用即删。

### 7.3 回滚

- **页面回滚**：`index.html.bak-<时间戳>` 改回 `index.html`（SFTP rename）
- **数据回滚**：链接整表存储于 nav_links，可通过面板 phpMyAdmin 导出/恢复；日常重要变更前建议先导出备份
- **彻底回退静态版**：删除 `api/` 目录，恢复最早备份的 index.html

## 八、常见问题排查（本部署实际遇到）

| 现象 | 原因 | 解决办法 |
|------|------|---------|
| SSH 里 mysql 命令连不上库 | 共享托管仅允许 Web 进程连库 | 数据库操作改走一次性 PHP 脚本（HTTP 触发，用完删除） |
| PHP 连库报 Access denied | 数据库密码≠面板密码 | 控制面板 Databases 页查看正确的库密码 |
| 面板登录被拦 | 面板启用 2FA | 需动态验证码；或改由用户已登录会话操作 |
| 面板内点击报 Security Warning | Webmin CSRF 检查拦截直接 URL | 必须从面板菜单内点击导航，勿直接贴 URL |
| 页面更新后无变化 | 浏览器/CDN 缓存 | Ctrl+F5 强刷；`Cache-Control: no-store` 仅对 API 生效 |
| 登录后编辑无效果/接口 401 | Session 过期或 Cookie 被浏览器策略拦截 | 重新登录；确认站点 HTTPS（Secure Cookie 需 https） |
| 保存显示成功但数据没变 | 前端整份替换逻辑下个别字段被校验丢弃 | 检查名称/URL/分组/色值是否符合 4.4 校验规则 |
| git push 到 GitHub 连接重置 | 出网 git 通道被干扰 | 改用 GitHub Git Data API（api.github.com 通道）构建提交 |

## 十、安全加固（2026-11-24 上线）：越权防护与纵深防御

### 10.1 加固目标与缺口清单

针对 Web 层水平越权（IDOR）与垂直越权（管理员功能被普通用户调用）两类风险，对本轮上线前的架构做差距分析，确认补强以下缺口（本章机制已全部上线并实测通过）：

| # | 上线前缺口 | 加固后机制 |
|---|-----------|-----------|
| 1 | CSRF 仅靠 `X-Requested-With` 头（非会话绑定、可被中间人/某些场景绕过） | 三层校验：同源（Origin/Referer 比对站点域名）→ 自定义头 → 会话绑定令牌（`hash_equals` 比对） |
| 2 | 无 IP 级登录限速，可横向枚举账号（换账号绕过单账号 5 次锁定） | `nav_ipguard` 表：15 分钟窗口内 20 次失败（含账号不存在）锁定该 IP 15 分钟，成功登录清零 |
| 3 | 无安全审计日志 | `nav_audit` 表记录：登录成功/失败（含原因与目标用户名）、账号锁定、IP 锁定/拦截、账号创建/改密/解锁/删除、登出 |
| 4 | 无会话空闲超时（Session 永久有效） | 30 分钟无操作强制清空会话并更换会话 ID（等效登出 + 防劫持） |
| 5 | `api/config.php` 可被 HTTP 直接请求（源码只输出空白，但属暴露面） | `api/.htaccess`：`Require all denied` 拒绝直接访问，返回 403 |
| 6 | 密码策略未禁止包含用户名 | 服务端 + 前端双重校验：创建/改密时密码包含目标用户名即拒绝 |
| 7 | 响应缺少安全头 | `.htaccess` 与 `json_out()` 统一输出 `X-Content-Type-Options: nosniff`、`X-Frame-Options`、`Referrer-Policy` |

> 水平/垂直越权的主体防护（服务端强制 owner 隔离、admin 接口 403、数据归属由会话推导而非参数指定）在本章之前已上线并经回归验证，本章为其补齐纵深防御层。

### 10.2 数据库变更（一次性迁移，执行后删除脚本）

```sql
-- IP 级登录限速
CREATE TABLE IF NOT EXISTS nav_ipguard (
  ip VARCHAR(45) NOT NULL PRIMARY KEY,
  fails INT NOT NULL DEFAULT 0,
  locked_until INT NOT NULL DEFAULT 0,
  last_attempt INT NOT NULL DEFAULT 0
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

-- 安全审计日志（约 1% 概率自动清理 90 天前旧记录）
CREATE TABLE IF NOT EXISTS nav_audit (
  id BIGINT UNSIGNED NOT NULL AUTO_INCREMENT PRIMARY KEY,
  ts INT NOT NULL,
  actor VARCHAR(64) NOT NULL DEFAULT '',
  ip VARCHAR(45) NOT NULL DEFAULT '',
  action VARCHAR(32) NOT NULL,
  detail VARCHAR(255) NOT NULL DEFAULT '',
  KEY idx_ts (ts),
  KEY idx_actor (actor)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

### 10.3 关键机制说明

1. **CSRF 令牌（会话绑定）**：首次访问 `GET api/auth.php?action=status` 生成 64 位十六进制令牌（`random_bytes(32)`）写入会话并随响应下发；此后所有写操作必须以 `X-CSRF-Token` 请求头回传，服务端 `hash_equals` 定长比对。登录与登出也强制校验（防跨站登录/登出伪造）；登出后立即下发新会话的新令牌。
2. **同源校验**：写请求必须携带 `Origin`（或 `Referer`）且与 `ALLOWED_ORIGIN` 常量（`https://techprobe.lxi.be`）一致；两者皆缺失视为非浏览器可疑请求，一律 403。
3. **IP 限速**：登录失败（无论账号是否存在）计入该来源 IP 的窗口计数；达阈值后 IP 锁定期间即使凭据正确也返回 429。仅信任 `REMOTE_ADDR`（共享主机无可信代理头，`X-Forwarded-For` 可伪造）。登录成功清除该 IP 记录。
4. **审计日志**：不记录明文密码；记录尝试的用户名（截断 32 字符）与失败原因（no-user/bad-pass）。写入失败不影响主流程（try-catch 包裹）。
5. **前端 `api()` 改造**：启动先 `GET status` 预取令牌；所有写请求自动携带 `X-CSRF-Token`；收到 `csrf` 错误（会话超时/登出轮换导致令牌失效）时自动重取令牌并重试一次；登录框区分「账号锁定」与「IP 被限制」两类提示。
6. **安全参数集中管理**：全部在 `api/config.php` 顶部常量区（`SESSION_IDLE_TIMEOUT`/`IP_FAIL_WINDOW`/`IP_FAIL_THRESHOLD`/`IP_LOCK_SECONDS`/`ALLOWED_ORIGIN`），调整后重新上传该文件即可。

## 十一、日志管理模块（2026-11-24 上线）

### 11.1 功能概述

基于第十章的 `nav_audit` 审计表，新增面向用户的日志管理模块，覆盖：**用户登录、用户退出、增加用户、删除用户、修改用户权限**（及其他既有审计事件：修改密码、解锁、账号/IP 锁定与拦截）。

每条日志审计记录包含以下审计要素：

| 字段 | 说明 |
|------|------|
| 操作时间 | `ts`（Unix 秒，前端渲染为 `YYYY-MM-DD HH:mm:ss`） |
| 操作人 | `actor`（登录类事件为具体用户名；来源不明的失败尝试显示为「未知来源」，detail 含尝试的用户名） |
| 操作内容 | `action`（事件类型，前端映射为中文）+ `detail`（如 `target=logtester role=user->admin`） |
| 操作 IP | `ip`（仅信任 REMOTE_ADDR） |

### 11.2 权限模型（服务端强制）

| 角色 | 可见范围 | 实现方式 |
|------|---------|---------|
| 管理员 | **全部审计日志**（含所有用户、匿名失败尝试、锁定事件） | `logs.php` 无过滤条件 |
| 普通用户 | **仅本人操作日志**（`actor = 自己`） | `logs.php` 服务端强制 `WHERE actor = ?`，前端传参无法越权 |
| 未登录 | 不可访问 | 401 |

普通用户看不到：他人日志、匿名的登录失败记录（含对他人账号的尝试）、管理员操作记录——防止借日志页面横向探测系统与用户信息。

### 11.3 接口设计（api/logs.php，GET）

- `page`：页码，默认 1
- `size`：每页条数，默认 50，上限 100（超限自动收敛）
- `action`：可选类型筛选，白名单校验（12 个合法动作 + `lock` 聚合值，聚合 IP 锁定/IP 拦截/账号锁定/账号拦截四类事件）
- 响应：`{ok, scope(all|self), role, logs[{id,ts,actor,ip,action,detail}], total, page, pages, size}`
- 排序：按 `id` 倒序（最新在前）；`page` 超出总页数时自动回收到末页

### 11.4 修改用户权限（admin.php 新增 action=change_role）

- 管理员专属（普通用户调用返回 403），校验 CSRF 令牌
- 防护：① 不允许修改当前登录账号自己的角色；② 不允许把系统内**最后一个**管理员降级为普通用户；③ 角色值白名单（user/admin）；④ 目标已是该角色时报错（幂等提示）
- 成功后落审计：`change_role  target=<用户名> role=<旧>-><新>`
- 前端入口：账号管理面板每个非本人账号的「设为管理员 / 设为普通用户」按钮（确认弹窗）

### 11.5 前端「日志」面板

- 顶部工具栏新增「日志」按钮（登录后可用，普通用户也可查看自己的日志）
- 面板内容：每条日志四要素（类型徽标 + 操作内容 + 操作人 + IP + 精确到秒的时间）
- 类型筛选下拉（9 项：全部/登录成功/登录失败/退出登录/创建账号/删除账号/修改权限/修改密码/解锁账号 + 锁定与拦截聚合）
- 底部分页条（上一页/下一页/页码，越界自动禁用）
- 普通用户视角显示「仅显示与你相关的操作记录」提示条；管理员视角无此限制提示
- 动作中文映射：login_ok→登录成功、login_fail→登录失败、logout→退出登录、create_user→创建账号、delete_user→删除账号、change_role→修改权限、change_pass→修改密码、unlock→解锁账号、ip_locked→IP 触发锁定、ip_blocked→IP 锁定拦截、account_locked→账号锁定、account_blocked→账号锁定拦截
